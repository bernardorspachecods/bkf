# Update to BKF format 0.2

## What changes

- Root-absolute Markdown links in a nested bundle (a bundle inside another
  bundle) now resolve from the outermost bundle root, not from the nested
  bundle's own root. A link such as `/format/glossary.md` in `bkf/` becomes
  `/bkf/format/glossary.md`. Links in the outermost bundle do not change.
- A link from one bundle to a file outside a nested bundle is allowed and
  checked, because it resolves from the outermost root.
- `bkf validate` of a nested folder climbs to the outermost bundle root, stopping
  at the git root (`.git`), so the checks match what the outermost bundle sees.

No document is renamed and no document is added or removed by this update.

## Steps

1. Commit the bundles, or back them up, so the edits can be reviewed and reverted.
2. Run `bkf upgrade --check <path>` from the repository root. It lists the
   bundles and files that would change, and exits `1` when anything would change.
3. Run `bkf upgrade <path>`. It prefixes the root-absolute Markdown links of each
   nested bundle that declares an older version, and it regenerates the map
   inventories of the chain.
4. Do not hand-edit the result. HTML relative links, plain-text paths and prose
   are not changed; review any such reference by hand. A bundle with no nested
   bundle changes only its `bkf_version`.
5. Set `bkf_version` to `"0.2"` in each migrated bundle's `MAP.md`. The command
   does this in step 3, so this step is the final check that it happened.

## Verify

- `bkf validate <outermost root>` reports no errors.
- `bkf inventory --check <outermost root>` reports no stale inventories.
- `bkf upgrade --check <path>` exits `0` and prints `already current`.
