# Repo library

- Propose a candidate; do not write it first. Name the activity, the rules or stages it would hold, and whether it is a module or a workflow; name the two or three closest existing entries and what each owns, so the user can correct the overlap check. Then wait for the answer.
- A candidate is a procedure or rule set the work has applied more than once, or one the user says always applies here, scoped to an activity (for example, editing the database). Prose about how the repository works, with no activity to act on, is not a candidate. Keep a candidate only if no hook or script can check it (if one can, write or extend the check instead; see [repo-maintenance](../repo-maintenance/SKILL.md)), and a capable agent would not follow it unprompted, it records a local preference, or it prevents a failure agents credibly show.
