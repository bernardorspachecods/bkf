# Run commands

The scripts of the agentic-work skill run on one engine, `agent-skills/harness`. Each takes the same commands: `<script> start ...`, `resume`, `status <name>`, `board <name>` and `finish <name>`. Start each `start` and `resume` with Bash `run_in_background: true` and stay quiet until it ends; the `guard` hook of `bkf hooks` refuses a launch in the foreground or one backgrounded by hand, including from an agent inside a run.

- **Backend.** Agents are Codex by default. `HARNESS_BACKEND=claude` runs a whole run on `claude -p`: give `-m` a Claude model such as `sonnet` and `-e` an effort from `low` to `max`. Set the variable on every `resume` too, or the run goes back to Codex.
- **State** is in `~/.<workflow>-runs/<repo>/<name>/` (`~/.plan-runs`), `<repo>` being the name of the repository's folder. `<WORKFLOW>_RUNS_DIR` or `HARNESS_RUNS_DIR` names the folder that holds the runs themselves, without the repository level, and `<WORKFLOW>_GUIDES` replaces the folder of role guides (by default the `roles/` folder of the skill). Do not create the folder by hand or point it under `/tmp`.
- **Progress.** `status.log` is the event history; `status` prints it and `board` prints a board of the steps and their agents, which is also saved as `board.txt`.
- **A run that stops** (an agent failed, a review escalated, the account ran out of quota) writes `STOPPED` in `status.log` with the reason. Read the rounds in the run folder, fix the cause (inputs are under `00-input/`), then `resume <name>`: finished steps stay done and the unfinished one runs again. A run that was killed is detected on `resume` and continues the same way.
- **A stalled agent.** An agent that writes nothing to its events and stderr files for `HARNESS_AGENT_STALL_TIMEOUT` seconds (default 1200, 0 turns it off) is ended and the run stops with `STALLED` in `status.log`. Fix the cause (a login, the network), then `resume`.
- **Usage limit.** The run stops with the reason `usage limit reached` and `status.log` gets `QUOTA: <the text after "try again at">`, as the agent wrote it, not parsed. Wake once, a little after that time, and `resume`: run `harness quota-wait '<that text>' && <script> resume <name>` with `run_in_background: true`. (`--margin`, default 120 s). When it cannot read the time it exits 2 without waiting: work out the time yourself and set one wake-up for it plus 2 minutes, never one at the time itself or before it, and if the quota is still out when it fires, add 2 minutes more instead of guessing again.
- **Lock.** A live script holds `<run>/.lock`; a second `resume`, a `finish` or a recovery command refuses while it does.
- **When it prints `READY`** the result is in the run folder. `finish <name>` copies the record to `records/plans/<name>/` in the repository and removes the run folder; `finish --discard <name>` deletes the run.
- **Limits** (environment variables): a review is capped at `<WORKFLOW>_MAX_ROUNDS` rounds (default 3), and must give at least `<WORKFLOW>_MIN_CHECKED` lines (default 3) under `## What I checked`, or it is repeated and then fails. Counts start again at every `resume`.
- **Sandbox.** Runs use the `workspace-write` sandbox. It confines writes to the agent's folder, but an agent can still read files outside the checkout, such as the login sessions of CLI tools in the home folder, and reach HTTPS, so it can use any session left open. The repository's own rules say what to keep logged out.
