# Coordinate a workflow

- Work assigned by a plan follows the coordinator's brief, level, and output locations. A change to the assigned question, scope, level, or output location goes to the coordinator, never to a stage agent to decide. Do not present provisional work as completed plan output.
- At a checkpoint on a document, give the user a link to the file and ask them to approve it or request changes; do not paste it into chat. After requested changes, link the revision and wait for approval of that version. Deliver a report as a link to its single canonical copy, not a second copy pasted into chat.
- The coordinator keeps the conversation with the user and prepares bounded briefs, but does not act as researcher, implementer, or reviewer, even when a plan has no subplans. Substantive gaps and unusable work go back to the assigned agent or a replacement instead of being filled by new research or review from the coordinator, and its check of each return (see delegate-work.md) is not a formal review: a formal reviewer is distinct from both the implementer and the coordinator. The coordinator may make small plan corrections with the user's agreement; changes to the deliverable go to an implementer.
- A unit's output is available downstream only after its work is complete, the coordinator has received and reconciled it, the applicable dependency, review, and integration gates are satisfied, and any required checkpoint is approved. A file existing, or a provisional result, unlocks nothing.
- Use one reviewer by default. Add reviewers only when independent perspectives or a distinct specialist view would materially improve the assessment, and give each a distinct question or angle.
- When independent perspectives are wanted, anonymize the outputs before they are reviewed: strip identity and perspective text, randomize the labels, and keep the key from the reviewers. Anonymization is imperfect, since distinctive arguments can still reveal an author.
- Do not deliver a synthesized report until a completeness review by an agent distinct from its author passes. On a revise, the same author updates it and the same reviewer rechecks it against the same sources.
- When a stage is meant to form its own view, its assignment names what it receives and what it does not: an evaluator gets the sources but not the collector's relevance verdicts, an auditor does not get the author's reasoning. Give a stage an earlier stage's verdicts only when it needs them. This is by instruction; nothing enforces it.
- A checkpoint applies after the flagged stage's artifact is complete: stop, tell the user to review it, and start no later step until they approve. In a parallel group, a flagged branch holds the steps that depend on it and the step that follows. Approval happens in the conversation and is not recorded in the workflow files. The checkpoints are fixed in the declaration; changing them is a declaration edit.
- When work fails, return it to the unit responsible for the affected result, usually the implementer; if an agent cannot proceed without missing guidance or a major assumption, pause and ask the user. A failed agent is not a block: assign a fresh agent the same mission with the same permitted inputs, without other agents' outputs unless the stage allows them, and keep the unit in progress. If no replacement is available, report the work as incomplete and ask the user; the unit is then blocked. A correction rewrites the response in the same stage file instead of adding stages, and loop limits belong to the workflow type.
- Keep the workflow's progress in the parent file's frontmatter; you are the only writer. Set `execution_status` (`not_started`, `in_progress`, `blocked`, `complete`) and list only the in-flight units in `unit_status`. When a review sends work back, re-list the earlier unit as `in_progress`. Use `blocked` only when waiting on a user decision, never for an agent failure. When the workflow finishes, set `complete` and clear `unit_status`. Never change the declaration block when updating status. To resume a stopped run, read these fields first.
